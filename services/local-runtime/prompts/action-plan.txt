你负责为新形象准备动作方案。输入 current_actions 为上一版的动作语义、运动描述与素材绑定，candidate_context 为这次形象的成长依据，skills 为已有可用技能。附件为当前形象与候选设计。
结合整体形象、气质、个性、经历和身体结构判断哪些动作仍然适合。合适的动作保留运动含义与节奏并更新形象；不合适的调整。新增动作必须有实际用途。蛋与孵化幼体的表达可以不同。不要按旧图数字继承动作。
current_actions.states 是上一版已有的静态状态，其 ID 同样属于既有语义绑定。让这些状态随孵化获得身体表达时，使用 adapted 并解释新的表达；只有此前不存在的动作 ID 使用 new。initial 是最初版本的展示标签，本轮继承判断仍按该 ID 的实际用途进行。
基础动作必须包含 base.idle、base.greet、sleep.rest、sleep.wake。持续睡眠必须是真正休息的姿势，不能用伸懒腰、闭眼开心或打招呼代替。为 skills 中每个技能准备 skill.<id>.startup/running/success/failed/cancelled，发动动作由你根据技能用途和宠物设计，不预先指定肢体。
输出 JSON {"actions":[{"id":"base.greet","name":"动作名称","description":"具体身体或整体动作、起止姿态和衔接","trigger":"什么时候播放","change":"inherited 或 adapted 或 new","reason":"为何保留、调整或新增","frames":[1,2,1,0],"fps":4,"loop":false}]}。
每个 frames 数字指一个关键姿态。0 起连续编号，每六格组成一页 3×2 图集，最多 18 格。每格必须至少被一项动作使用，避免无用素材。可复用兼容姿态；同一个动作可使用多个关键姿态表现实际运动，不能把无关动作当连续帧。描述需说明每格相对姿态的变化，供素材生成使用。日常待机和睡眠不共享姿态。基础动作一般一页即可；确有技能素材需求时再增加页。新旧动作 ID 相同则 change 为 inherited 或 adapted；只有之前不存在的 ID 才标 new。
保持描述简洁，避免重复成长背景：name、trigger 各用短语，description 说明必要姿态变化，reason 一句解释关系。fps 与 loop 表示播放速度及是否循环；非循环动作回到适合的待机姿态。
同一动作的 frames 应是同一个短动作按时间推进的姿态，相邻姿态说明运动如何继续，不把整套动作的不同代表姿势拼成一个序列。静态待机/睡姿可以保持单帧。预算不足时优先短小、完整且用途明确的动作，不堆叠多个含义，也不靠提高 fps 冒充连续运动。合适的上一版动作仍保留原运动与节奏。
delivery_budget 给出本轮可用素材页数与每页格数，只约束交付资源，不决定宠物的成长方向。在该预算内优先保证必要的待机、互动、睡眠、唤醒和已有技能动作；合理复用关键姿态。新动作数量不需要随进化递增，避免为可选表达过度增加素材。可以为有用的新表达命名其他稳定动作 ID，沿用“用途.动作”的命名形式。
在输出中另外提供 poses 数组，逐一明确每个全局姿态编号对应的具体身体姿态和表情：{"poses":[{"index":0,"description":"这一格应该呈现的具体姿态"}],"actions":[...]}。poses 覆盖所有素材格，不让素材生成 Agent 自行猜测动作序列中的编号是什么。
